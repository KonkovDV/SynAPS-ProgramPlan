# SynAPS-ProgramPlan changelog

## Не выпущено

### Рабочее место планировщика (F5)

- Команда `serve`: отчёт как рабочее место — данные с сервера, проверка правок, пересчёт, решения, журнал, выгрузка плана в JSON и MS Project XML.
- Режим правки на диаграмме Ганта: перетаскивание мышью, сдвиг клавишами ← → (Shift — 5 рабочих дней), отмена, сброс, выгрузка правок в JSON; исправленные работы и их прежнее положение видны на диаграмме.
- Мгновенная проверка правок независимой проверкой: нарушения с кодами и сравнение показателей «вариант / с правками». В статическом отчёте — предварительная проверка в браузере.
- Пересчёт с закреплёнными правками: по умолчанию «минимум перестановок» (ни одна работа не раньше исходного варианта, минимум суммарного запаздывания), по выбору — переоптимизация сроков; переход к переоптимизации записывается. Новый вариант R публикуется только при `outcome.ok`.
- Решения «принять / отклонить» с обоснованием; журнал с хеш-цепочкой SHA-256, пользователем, ролью, хешем плана и входа; команда `journal` проверяет целостность.
- Роли планировщика, руководителя и наблюдателя по токенам из `SYNAPS_PROGRAMPLAN_TOKENS` (допускается хеш токена); без ролей — только локальный адрес. Заголовки безопасности и CSP.
- Варианты с правками сохраняются и после перезапуска восстанавливаются только при совпадении хеша с журналом и чистой проверке; нумерация продолжается.
- Команды `check --moves` и `replan --moves --mode`; запрос `POST /check` вычислительного HTTP-контура.
- Выгрузка принятого плана пишет базовый план 0: даты, с которыми план сравнивался. На диаграмме Ганта ОКР и этап сворачиваются, есть отбор по предприятию и ресурсу, у вехи с оценкой P80 — зелёная или красная точка. Длинный список рисует только видимые строки.
- Противоречие максимальных задержек проверяется и тогда, когда в графе связей уже есть цикл. Имена в отчёте не могут закрыть блок данных. Чужой адрес вычислительного HTTP без HTTPS получает отказ, даже с токеном. Сверх предела ресурсов, горизонта, исключений календаря или драйверов риска программа не принимается.
- У работы можно указать изделие, конфигурацию и опытный экземпляр. Экземпляр занимает ресурс ёмкости 1, поэтому два его испытания не идут одновременно. Команда `ask` по умолчанию выключена: при заданных ключе и каталоге Yandex Cloud она составляет записку только из фактов принятого плана и отбрасывает фразу без такой ссылки.
- Выгрузка принятого плана пишет начало и конец горизонта. Обратный импорт этого файла снова проходит проверку: дата статуса остаётся внутри горизонта. Вариант, посчитанный на изменённой программе (второй стенд, снятая ОКР), в отчёте остаётся в таблице сравнения и не рисуется на диаграмме исходной программы.
- Учебная программа в показе называется «Учебная программа ОКР». Пик 100 % в таблице — ресурс выбран целиком, не перегрузка. Вердикт `OPTIMAL` относится к цели своего варианта.
- Причина переноса называет код ОКР, а не внутренний идентификатор.
- У работы есть процент выполнения. Решатель не двигает фактическое начало. Прогноз остатка начатой работы начинается с даты статуса; окончание раньше этой даты — нарушение `FORECAST_BEFORE_STATUS`, сдвиг факта — `STARTED_MOVED`. На диаграмме четыре полосы: база, текущий план, факт и прогноз. Выгрузка в MS Project XML пишет процент, факт и остаток и читается обратно без потерь. XER по-прежнему читает факт и, если колонка есть, процент; своей записи XER нет.
- `analyze` помечает большую задержку связи кодом `HIGH_LAG`. Пороги длинной работы, доли жёстких дат и большой задержки вынесены в `LIMITS.md` и меняются переменными окружения: это стартовые значения пилота, не норматив.
- У причины переноса есть факт: тип, ресурс, ОКР, работа-блокер, даты, хеш плана и хеш входа. Фраза собирается из этих полей, а дата, которой нет у работы или блокера, отвергается. Запрос к языковой модели без фактов отклоняется.
- У ещё не начатой работы может быть несколько режимов: своя длительность и свои ресурсы у каждого. CP-SAT оставляет ровно один; в плане, на диаграмме и в причине `MODE_SELECTION` виден выбранный код. Длительность работы в файле — самый короткий режим. Жадный диспетчер режимы не считает и ставит `UNSUPPORTED_MODEL`, дат нет. Чужой код режима и чужие ресурсы план не принимают (`MODE_UNKNOWN`, `MODE_DEMAND`). Цель решателя по-прежнему просрочка и окончание, отдельного риска режима нет.
- У стенда есть состояния и матрица переналадки. Между разными состояниями решатель оставляет интервал, его видно на диаграмме и в причине `SETUP_TRANSITION`. Короткий интервал и наложение переналадки на работу — `CHANGEOVER_SHORT` и `CHANGEOVER_OVERLAP`. Несовместимая конфигурация — отказ при чтении. К длительности работы дни переналадки не прибавляются. Опытный экземпляр по-прежнему ёмкость 1. Ядро: режимы в [SynAPS#46](https://github.com/KonkovDV/SynAPS/pull/46), переналадка на другом рабочем центре в [SynAPS#47](https://github.com/KonkovDV/SynAPS/pull/47); в `main` ядра ещё не влито.
- Команда `diff` сравнивает две версии программы: работы, связи, ресурсы, проекты и даты. Файл без `schema_version` читается как текущая схема `SynAPS-ProgramPlan.program.v1`. Неизвестная версия — отказ с кодом 2. Хеш входа считается по каноническому JSON и не зависит от порядка ключей.
- Политика безопасности отчёта больше не разрешает произвольный встроенный сценарий: файл отчёта пускает сценарий по хешу SHA-256, рабочее место — по одноразовому ключу ответа. Стили остаются встроенными, потому что цвета задаёт сценарий страницы.
- Команда `build_evidence.py --check` сверяет число тестов и цифры показа в документах с `evidence.json` и с собранными тестами. Пропуск теста роняет прогон. GitHub Actions закреплены по SHA коммита, а не по плавающему тегу. `/solve` и выгрузка варианта из рабочего места не отдают даты, если хеш плана не совпал.
- Команда `doctor` проверяет стенд без расчёта и без сети: Python, ядро SynAPS с полным коммитом, OR-Tools, обязательные библиотеки, выключенную языковую модель. С `--demo` она сверяет каждый план каталога показа с программой по хешам и отчёт с планом A. Набор для установки без сети теперь содержит колесо самого продукта, потому что установка из исходников без сети не собирается. Инструкция для стенда заказчика — `docs/acceptance/demo-stand.md`.
- Причина варианта «что если» читается по изменённой программе, а не по исходной. Если хеш входа в плане не совпадает с этой программой, объяснение считается разрывом. Команда `demo` пишет `plan.xml` принятого плана.
- Причина читает запас ёмкости, с которым вариант был посчитан. Нехватка из‑за запаса не называется отпуском; если в тот же день ресурс занят другой работой, называется она.

### Риск срыва (F3)

- Реестр драйверов риска: поле `risk_drivers` и лист Excel `Risks` (вероятность, множители, работы, владелец).
- Оценка риска: доля выборок «в срок» по вехам, доля выборок с соблюдением всех директивных сроков, ранжирование драйверов по выигрышу P80 на общих случайных числах.
- Раздел риска в отчёте и рабочем месте (`report --risk-runs`, `serve --risk-runs`), `risk --out` и `--brief`; демонстрация считает риск варианта A.
- Исправлено: выполненные работы больше не занимают ресурсы в выборке; ранние даты работ ограничивают выборку; связи с максимальным лагом сохраняют свой минимальный лаг (раньше выпадали из выборки целиком).

### Импорт и проверка (F1, качество)

- Импорт Primavera P6 XER: несколько проектов в одном файле, межпроектные связи, статусы, ограничения, ресурсы; пропущенное — в отчёте импорта.
- Импорт MS Project MPP и MPX через MPXJ (Java 17, необязательный пакет `mpp`); сопоставление полей такое же, как у XML.
- Чтение PSPLIB и скрипт прогона `scripts/bench_psplib.py`: j30, j60, j120 и RCPSP/max j10, j20, j30. Результаты — `benchmarks/psplib_j30.json`, `psplib_j60.json`, `psplib_j120.json`, `benchmarks/rcpspmax_*.json`.
- PSPLIB j120, 600 задач по 120 работ, лимит 10 с, `seed` 42: все 600 планов приняты, 259 с доказанным оптимумом, среднее отклонение от критического пути 36,84 %, среднее время 7,43 с.
- Замер масштаба на учебных программах `scripts/bench_scale.py`: принятый план до 64 ОКР и 2 688 работ (`benchmarks/scale.json`).
- Граница первого допустимого плана `scripts/bench_boundary.py`: 5 010 работ приняты за 117,8 с (1 221 МБ). 8 700 работ упираются в 120 с жадного поиска. 10 020 работ не входят в модель ядра: рабочих центров больше 10 000 (`benchmarks/scale_boundary.json`).
- Вариант P «Приоритет»: ОКР планируются по убыванию приоритета, даты вех и окончаний старшего уровня закрепляются.
- Журнал: печать головной записи (`<журнал>.head`) обнаруживает обрезку хвоста и замену файла; `journal --anchor` сверяет хеш, сохранённый вне системы; `journal --seal` ставит печать и не затирает уже расходящуюся.
- Пересчёт с минимумом перестановок раскладывает сдвиги на правку, последователей, общие ресурсы и работы без связи с правкой. Порог пилота считается по последней группе.
- `serve` вне локального адреса требует TLS и роли. Прокси корпоративного входа передаёт пользователя секретом `SYNAPS_PROGRAMPLAN_PROXY_SECRET`.
- Импорт XER проверен на файле, записанном MPXJ, а не только на файле, собранном вручную.
- `POST /check` отвечает 200 только если план принят, хеши программы и плана сходятся и жёстких нарушений нет. Непринятый план — 409, даже если даты сами по себе чистые. Тот же шлюз у отчёта, экспорта, риска и `check`. Непринятый пересчёт в файл не пишется.
- Предел числа работ и связей (`SYNAPS_PROGRAMPLAN_MAX_TASKS`, `SYNAPS_PROGRAMPLAN_MAX_LINKS`). Книга Excel с раздутой распаковкой не читается. `SYNAPS_PROGRAMPLAN_MEMORY_MB` считает план в отдельном процессе и останавливает его по потолку памяти. Модель угроз — `docs/threat-model.md`.
- Сдвиги варианта: взвешенная сумма рабочих дней, смена порядка работ на стенде, сдвиги внутри окна заморозки.
- `scripts/anonymize_program.py` заменяет имена кодами и сдвигает даты на постоянное число дней. Результат в репозиторий не кладётся.
- `scripts/fetch_wheelhouse.py` собирает каталог колёс и `requirements-hashed.txt` с хешами SHA-256 для установки без сети.
- ALNS и RHC ядра проверены и в команду не выведены: на задаче с обобщёнными связями они сразу возвращают `precedence_edges_unsupported`. Ошибка ядра теперь попадает в текст вердикта, а не теряется.
- Оценка риска отбрасывает выборку, нарушившую максимальный лаг, в том числе когда предшественник уже выполнен: его даты берутся из принятого плана, а не обнуляются. Драйверы с одной `group` наступают от одного случайного числа.
- Поставка для закрытого контура: `LICENSE`, `NOTICE` (LGPL MPXJ), `requirements.lock`, SBOM, руководство администратора, техническое задание и программа испытаний.
- Исправлено: сценарий «без ОКР» оставлял в реестре рисков ссылки на работы исключённой ОКР.
- Импорт пишет потери кодами (`skipped`, `approximated`, `clamped`, `info`). `import --losses` сохраняет JSON, `import --strict` не записывает программу, если семантика потеряна или приближена.
- Экспорт принятого плана в MS Project XML добавляет ресурсы, назначения, директивный срок и хеш плана. Обратное чтение этого файла сохраняет даты, тип связи и лаг.
- Таблица `--aliases` объединяет ресурсы с разными именами. Похожие имена, которых в таблице нет, попадают в отчёт и не сливаются.
- Свидетель невыполнимости пишет «Достаточно ослабить любое из них», когда снятие каждого требования из набора по отдельности делает программу выполнимой, и «нужно ослабить весь набор», когда ни одного не хватает.
- `scripts/acceptance_run.py` собирает протокол из уже измеренных прогонов. Подписи ставятся на стенде. Уровень лабораторного подтверждения скрипт не поднимает.
- Вычислительный HTTP: тело больше 32 МиБ отклоняется, адрес вне локального без токена тоже. Если токены заданы, нужен `Authorization: Bearer`. `SYNAPS_PROGRAMPLAN_RATE_PER_MIN` ограничивает число запросов с одного адреса за минуту.
- Журнал подписывает записи ключом `SYNAPS_PROGRAMPLAN_JOURNAL_KEY` (HMAC-SHA256). Проверка с другим ключом журнал не принимает. Без ключа подпись не требуется.
- `explanation_gaps` сверяет сохранённый текст объяснения с повторным чтением того же плана.

### Документация

- В пилоте, техническом задании и README записаны заказчик (Объединённая двигателестроительная корпорация) и запрос №1: сводный план программы ОКР. Условие зрелости из карточки запроса стоит в реестре утверждений как условие запроса.
- Справочник этапов ОКР вынесен в `okr_stages.json`. У ОКР появилось предприятие-исполнитель: сроки и загрузка стендов сводятся по нему.
- README, руководство, форматы данных, справочник кодов, методология, архитектура, качество, безопасность, пилот, глоссарий, трассировка, границы и реестр утверждений обновлены под рабочее место, риск, XER и PSPLIB.
- Границы применения, README, методология, глоссарий, архитектура, трассировка и техническое задание согласованы с режимами и переналадкой. Вердиктов семь, включая `UNSUPPORTED_MODEL`. Проверок качества исходных данных девять. Журнал обнаруживает правку записи внутри файла; подмена файла вместе с печатью обнаруживается внешним якорем.
- Ранее в этом выпуске: документация для заказчика, команда `export`, цель `--objective stability` в командной строке, пустые необязательные колонки Excel, тест независимости проверки от решателя.

## 0.1.0 — 2026-10-05

Первый экспериментальный контур сводного плана программы ОКР на ядре SynAPS.

- Компиляция программы в задачу ядра: цепочки FS/0, остальные связи как FS/SS/FF/SF с лагами, пулы компетенций, отпуска и ремонты, вехи как мгновенные события.
- План принимается только после проверки ядра и независимой доменной проверки.
- Конфликты исходных планов, варианты A–E, объяснение сдвига, свидетель невыполнимости, перепланирование на новую дату статуса.
- Импорт и объединение MS Project XML, книга Excel, самодостаточный HTML-отчёт.
- Оценка риска P50/P80/P90 по принятому плану и HTTP-контур, который не отдаёт 200 на непринятый план.
- В SynAPS добавлены рёбра предшествования FS/SS/FF/SF; набор тестов FJSP сохраняется.
