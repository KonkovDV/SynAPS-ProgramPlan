# Данные и безопасность

Правила обращения с данными заказчика и меры безопасности SynAPS-ProgramPlan. Документ описывает и то, что уже обеспечено кодом, и то, что должен обеспечить контур заказчика.

## 1. Правила обращения с данными

1. **Только обезличенные данные.** Фамилии, названия изделий, шифры тем и организаций заменяются кодами до передачи в систему. Для расчёта нужны структура работ, длительности, связи, сроки и ёмкости, а не имена.
2. **Только в закрытом контуре.** Расчёт выполняется локально: командная строка, рабочее место и HTTP-контур не обращаются во внешнюю сеть, отчёт открывается без интернета (без внешних скриптов, шрифтов и CDN).
3. **Не в git.** Данные заказчика никогда не попадают в репозиторий. `.gitignore` исключает рабочие каталоги (`out/`), а демонстрация и тесты используют только синтетику.
4. **Происхождение обязательно.** У каждой программы есть поле `provenance`: `synthetic`, `open_data`, `customer_anonymized` или `experiment`, источник и хеш исходного файла. Происхождение переходит в доказательную базу каждого плана и показывается на первом экране отчёта.

## 2. Правила для искусственного интеллекта

- Языковая модель **не создаёт ограничения** и **не меняет план** без проверки.
- Объяснения строятся **только из структурированных фактов** итогового проверенного плана: активное ограничение, связь, занятый ресурс, календарь.
- Модель может только переформулировать уже вычисленные факты; в версии 0.1.0 языковая модель не используется вовсе.
- Ни один план не попадает в отчёт, экспорт, рабочее место или HTTP-ответ 200 без `outcome.ok`; ручная правка проверяется той же независимой проверкой.

## 3. Что обеспечено в коде

| Мера | Как реализовано |
|---|---|
| Безопасный разбор XML | MS Project XML читается через `defusedxml`: внешние сущности, DTD-атаки и «XML-бомбы» отклоняются |
| Строгая проверка входа | Модель Pydantic в строгом режиме: неизвестные поля, неверные типы и висячие ссылки отклоняются с кодом выхода 2 или HTTP 422 |
| Отказ по умолчанию | Непринятый план не отдаётся: HTTP 409, код выхода 1, экспорт и риск отказываются работать |
| Отсутствие хранения | Вычислительный HTTP-контур не хранит программы и планы; рабочее место хранит только журнал решений и варианты с правками в указанном каталоге |
| Автономный отчёт | HTML без внешних ресурсов, все данные встроены в файл; политика безопасности содержимого (CSP) запрещает загрузку чего-либо извне и отправку форм |
| Целостность | Хеш входной программы, настроек и плана в доказательной базе; ядро зафиксировано полным коммитом; журнал решений связан хеш-цепочкой |
| Без выполнения внешнего кода | Импорт не выполняет макросы и формулы: книга Excel читается в режиме значений |
| Разграничение прав | Рабочее место: роли планировщика, руководителя и наблюдателя, проверка права на каждом запросе, отказ по умолчанию (401/403) |
| Заголовки ответа | `Content-Security-Policy` (`default-src 'none'`, запросы только к своему серверу, запрет встраивания в чужие страницы), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store` |

## 4. Роли и доступ к рабочему месту

**Локальный режим** — без настройки. Один пользователь `local` с ролью планировщика. Сервер принимает запросы только с заголовком `Host` локального адреса (`127.0.0.1`, `localhost`, `::1`): так браузер на той же машине не может быть использован чужой страницей через подмену DNS (DNS rebinding). Запуск `serve` на другом адресе без ролей отклоняется с кодом выхода 2.

**Режим с ролями.** Администратор задаёт до запуска переменную окружения:

```text
SYNAPS_PROGRAMPLAN_TOKENS=<токен>=planner:ivanov,<токен>=manager:petrova,sha256:<хеш токена>=observer:sidorov
```

- Каждый элемент — `токен=роль:пользователь`; роли — `planner`, `manager`, `observer` (права — в [руководстве](user-guide.md#11-рабочее-место-планировщика)).
- Вместо самого токена можно указать `sha256:` и его хеш SHA-256 в шестнадцатеричном виде: тогда секрет не хранится даже в окружении сервера. Сравнение выполняется по хешу за постоянное время.
- Токен передаётся в заголовке `Authorization: Bearer`; браузер хранит его в памяти вкладки (`sessionStorage`) до её закрытия. Куки не используются, поэтому подделка межсайтовых запросов (CSRF) неприменима.
- Токены должны быть длинными и случайными (не меньше 32 случайных байт, например `python -c "import secrets; print(secrets.token_urlsafe(32))"`): ограничения числа попыток в рабочем месте нет.
- Пользователь и роль из токена попадают в каждую запись журнала.

**Сеть.** Рабочее место не реализует TLS. За пределы одной машины его выводят только за обратным прокси заказчика с TLS, а при наличии корпоративного входа — с аутентификацией на прокси.

## 5. Журнал решений

Журнал (`decisions.jsonl`) только дописывается. Каждая запись содержит хеш SHA-256 предыдущей и свой хеш, поэтому команда `journal` и рабочее место обнаруживают:

- изменение любой записи;
- удаление или перестановку записи внутри журнала;
- нарушение нумерации.

Чего цепочка **не** обнаруживает:

- удаление последних записей целиком;
- полную перезапись журнала тем, у кого есть права на запись файла.

Поэтому в контуре заказчика: права на запись журнала — только у учётной записи сервера; хеш последней записи (`journal decisions.jsonl --tail 1`) периодически фиксируется вне системы — в протоколе совещания, системе документооборота или отдельном журнале; файл входит в резервное копирование. Варианты с правками (`plan_R*.json`) после перезапуска подгружаются, только если их пересчитанный хеш совпадает с журналом и независимая проверка чиста, поэтому подменённый файл плана не попадёт в интерфейс.

## 6. Что должен обеспечить контур заказчика

- **Сеть.** Вычислительный HTTP-контур не имеет аутентификации: только локальный адрес или прокси с аутентификацией и TLS. Рабочее место — см. раздел 4.
- **Доступ к файлам.** Каталоги с программами, планами и журналом защищаются средствами ОС; отчёт HTML содержит все данные программы и должен храниться как сама программа.
- **Установка.** Устанавливать из проверенного зеркала с зафиксированными версиями; при установке без сети заранее собрать пакеты (`pip download`) и проверить их хеши.
- **Токены.** Выдача, хранение и отзыв токенов (отзыв — удаление из переменной и перезапуск) — процедура администратора контура.

## 7. Ограничения и план

- Нет входа через корпоративный каталог (LDAP, Kerberos, OpenID Connect), срока действия токенов и ограничения числа попыток — это задачи прокси или следующей версии.
- Одновременная правка несколькими пользователями не согласуется: каждый правит свою копию, а пересчёты выполняются по очереди.
- Ограничение размера входных файлов не установлено: очень большая книга Excel может занять много памяти. Число правок в одном запросе рабочего места ограничено 5000.
- Формальная модель угроз, перечень компонентов (SBOM) и соответствие требованиям ФСТЭК России к безопасности значимых объектов КИИ (приказ №239) не оформлены; это задача перед опытной эксплуатацией.
- Включение в Единый реестр российского ПО не проводилось.
