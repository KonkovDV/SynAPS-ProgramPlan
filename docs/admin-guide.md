# Руководство администратора SynAPS-ProgramPlan

Для контура без выхода в интернет. Продукт — лабораторный прототип: расчёт выполняется на машине заказчика, наружу ничего не отправляется.

## 1. Что ставится

- Python 3.12.
- Пакеты из `requirements.lock` в корне репозитория. Файл собран командой `python scripts/write_delivery.py` на машине, где продукт уже установлен. Перед переносом на другую операционную систему или другой процессор команду нужно повторить там, где есть сеть, и заново скачать колёса: версии с Windows не обязаны подойти к Linux.
- Ядро SynAPS ставится по коммиту из `requirements.lock`, не по ветке.
- Для рабочего места — дополнительные пакеты `fastapi`, `uvicorn`, `httpx` (дополнительные зависимости `api`).
- Для файлов MPP и MPX — Java 17 и пакеты `mpxj`, `JPype1` (дополнительные зависимости `mpp`). Библиотека MPXJ распространяется по LGPL-2.1; условия — в файле `NOTICE`. Без этой дополнительной зависимости Java не нужна.
- Состав библиотек — `sbom.cdx.json` (CycloneDX).

Проверено на Windows и в CI на Ubuntu. Astra Linux и РЕД ОС — производные Linux, пакеты manylinux на них обычно ставятся; при развёртывании контура установка повторяется на целевой системе и заносится в протокол.

## 2. Офлайн-установка

На машине с сетью, той же ОС и тем же процессором, что у контура:

```text
python scripts/fetch_wheelhouse.py
```

Скрипт скачивает пакеты из `requirements.lock` в каталог `wheelhouse` и записывает `requirements-hashed.txt`: у каждого пакета хеш SHA-256 скачанного файла. Каталог `wheelhouse` в репозиторий не входит. Если переменная `SYNAPS_SOURCE` указывает на каталог ядра с тем же коммитом, что в `requirements.lock`, в набор попадает и его колесо. Для другой ОС или другого процессора скрипт запускают там, а не на машине сборки Windows.

Каталог `wheelhouse`, `requirements-hashed.txt` и исходники переносятся в контур на съёмном носителе. В контуре:

```text
python -m pip install --no-index --find-links wheelhouse -r requirements-hashed.txt
```

Проверка, что сеть не нужна для расчёта: `SynAPS-ProgramPlan version` печатает имя, версию и полный коммит ядра. Команды `demo`, `solve`, `serve` после этого не обращаются к внешним адресам. Прогон на Astra Linux и РЕД ОС делается на самой этой системе и в протокол контура заносится отдельно.

## 3. Рабочее место

По умолчанию сервер слушает только локальный адрес и не требует сертификата:

```text
SynAPS-ProgramPlan serve program.json plan_A.json --journal decisions.jsonl --port 8765
```

Адрес кроме `127.0.0.1`, `localhost` и `::1` без ролей и без пары `--tls-cert` / `--tls-key` не запускается (код выхода 2). Рекомендуемая схема: процесс на локальном адресе, перед ним обратный прокси контура с TLS.

Корпоративный вход делает прокси. Он передаёт уже проверенного пользователя:

- заголовок `X-Remote-User` — учётная запись;
- заголовок `X-Remote-Role` — `planner`, `manager` или `observer`;
- заголовок `X-Synaps-Proxy-Secret` — секрет, совпадающий с переменной `SYNAPS_PROGRAMPLAN_PROXY_SECRET`.

Без верного секрета заголовок пользователя игнорируется. Неверный секрет — отказ, а не локальный режим. Срок жизни сессии и число попыток входа задаёт прокси: в самом продукте их нет.

Роли без прокси задаются переменной `SYNAPS_PROGRAMPLAN_TOKENS` (`токен=роль:пользователь` или `sha256:<хеш>=роль:пользователь`). Токен длинный, случайный. Отзыв — убрать строку и перезапустить процесс. Вычислительный HTTP запускается отдельно от рабочего места. `SYNAPS_PROGRAMPLAN_RATE_PER_MIN` — сколько запросов с одного адреса он принимает за минуту. `SYNAPS_PROGRAMPLAN_JOURNAL_KEY` — ключ подписи записей журнала; проверка `journal` с другим ключом журнал не принимает.

## 4. Журнал и файлы

Каталоги программы, планов и журнала доступны на запись только учётной записи службы. Рядом с журналом продукт пишет печать `<журнал>.head`. Её хеш последней записи периодически копируют в протокол вне этих двух файлов и сверяют:

```text
SynAPS-ProgramPlan journal decisions.jsonl --anchor <хеш>
```

Одновременная подмена журнала и печати без этого внешнего хеша не обнаруживается.

Данные заказчика в репозиторий и в каталог поставки не кладут. В поле `provenance` программы для них указывают `customer_anonymized`.

## 5. Обновление

Новая поставка — новый коммит ядра в `requirements.lock` и новый `sbom.cdx.json`, затем полный прогон `python -m pytest tests` и `python scripts/lint_claims.py` на машине сборки. На контуре ставят только собранный wheelhouse.
