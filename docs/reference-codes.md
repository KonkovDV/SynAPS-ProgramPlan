# Справочник кодов

Все коды, которые SynAPS-ProgramPlan выдаёт в ответах, файлах планов и отчёте. Коды стабильны и предназначены для автоматической обработки; рядом всегда идёт текст на русском.

## Вердикт плана (`outcome.claim`)

| Вердикт | `ok` | Когда ставится | Чего не означает |
|---|---|---|---|
| `OPTIMAL` | да | CP-SAT доказал оптимум цели ядра на скомпилированной задаче; проверка ядра и доменная проверка чисты | Оптимум сразу по всем целям заказчика; оптимум после эвристической привязки людей |
| `FEASIBLE` | да | CP-SAT нашёл допустимый план в лимите времени; обе проверки чисты | Доказанный оптимум |
| `HEURISTIC_FEASIBLE` | да | Жадный диспетчер (`--solver greedy`); обе проверки чисты | Оптимум; доказательство невыполнимости при отказе |
| `INFEASIBLE` | нет | CP-SAT доказал невыполнимость исходной модели — без подъёма окон и без второй фазы привязки людей | «Не нашлось за отведённое время» |
| `REJECTED` | нет | Решатель вернул расписание, но проверка ядра или доменная проверка нашла жёсткое нарушение | — |
| `ERROR` | нет | Плана нет, невыполнимость не доказана: истёк лимит времени, работал жадный план или упрощённая модель | Невыполнимость |

Только планы с `ok = true` попадают в Гант, экспорт в MS Project, оценку риска и HTTP-ответ 200.

## Нарушения независимой проверки

Проверка (`checker.py`, команда `check`, проверка правок в рабочем месте) читает программу и даты плана и не использует решатель. Важность: `hard` — план не принимается; `kpi` — отклонение показателя, план принимается; `warning` — к сведению.

Чаще всего при ручной правке встречаются `PRECEDENCE_FS_BROKEN` (работа поставлена раньше окончания предшественника или последователь не сдвинут вслед), `CAPACITY_EXCEEDED` и `SKILL_POOL_EXCEEDED` (на новые даты ресурс или компетенция уже заняты), `DEADLINE_MISSED` и `DUE_MISSED` (веха или работа ушла за срок), `SHIFT_LIMIT_EXCEEDED` (превышен допустимый сдвиг). Предварительная проверка в статическом отчёте использует те же коды, но проверяет только связи, максимальные лаги, сроки и загрузку поимённых ресурсов.

| Код | Важность | Что нарушено |
|---|---|---|
| `UNKNOWN_TASK` | hard | В плане работа, которой нет в программе |
| `DUPLICATE_TASK` | hard | Работа в плане дважды |
| `MISSING_TASK` | hard | Работа программы отсутствует в плане |
| `DONE_MOVED` | hard | Выполненная работа сдвинута с фактических дат |
| `FROZEN_MOVED` | hard | Сдвинута работа из зоны заморозки |
| `STARTED_MOVED` | hard | Сдвинуто фактическое начало уже начатой работы |
| `FORECAST_BEFORE_STATUS` | hard | Прогноз окончания остатка раньше даты статуса |
| `PINNED_MOVED` | hard | Сдвинута закреплённая работа |
| `CALENDAR_BROKEN` | hard | Начало или окончание на нерабочем дне |
| `DURATION_MISMATCH` | hard | Длительность в плане не совпадает с программой (или с остатком выполняемой работы) |
| `HORIZON_BROKEN` | hard | Работа вне горизонта или раньше даты статуса |
| `WINDOW_BROKEN` | hard | Нарушено «не раньше» |
| `DEADLINE_MISSED` | hard | Нарушен директивный срок работы или ОКР |
| `DUE_MISSED` | kpi | Нарушен плановый срок (учитывается как просрочка) |
| `SHIFT_LIMIT_EXCEEDED` | hard | Сдвиг относительно утверждённых дат больше лимита |
| `PRECEDENCE_FS_BROKEN`, `PRECEDENCE_SS_BROKEN`, `PRECEDENCE_FF_BROKEN`, `PRECEDENCE_SF_BROKEN` | hard (warning для мягкой связи) | Связь нарушена: зазор меньше лага |
| `MAX_LAG_BROKEN` | hard (warning для мягкой связи) | Зазор больше максимального лага |
| `CAPACITY_EXCEEDED` | hard | Загрузка ресурса в какой-то день больше доступной (с учётом отпусков и ремонтов) |
| `SKILL_UNBOUND` | hard | Потребность в компетенции не закрыта человеком там, где пул неточен |
| `SKILL_MISMATCH` | hard | Назначен человек без нужной компетенции |
| `SKILL_POOL_EXCEEDED` | hard | Суммарная потребность в компетенции больше числа людей с ней |
| `SKILL_BINDING_ADVISORY` | warning | Пул точен, люди названы рекомендательно |
| `APPROXIMATED_RELATION` | warning | Связь в режиме `windows` учтена приближённо (выставляет планировщик) |

## Конфликты исходных планов

Команда `analyze` и раздел отчёта «Конфликты исходных планов». Считаются по датам, как они пришли из планов ОКР, до оптимизации.

| Код | Что найдено |
|---|---|
| `OVERLOAD` | Ресурс перегружен в исходных планах |
| `SHARED_CONTENTION` | Перегрузка общего ресурса работами двух и более ОКР |
| `SKILL_POOL_OVERLOAD` | Потребность в компетенции больше числа людей с ней |
| `LINK_BROKEN` | Исходные даты нарушают связь |
| `DEADLINE_IMPOSSIBLE` | Срок недостижим даже без учёта ресурсов (отрицательный резерв по методу критического пути) |
| `DEADLINE_AT_RISK` | Резерв мал, выше по цепочке есть перегрузки |
| `DEADLINE_MISSED_IN_SOURCE` | Исходный план уже нарушает срок |

## Качество данных

Поле `quality` в ответе `analyze`.

| Код | Что найдено | Почему важно |
|---|---|---|
| `DANGLING` | Работы без связей | Не влияют на сроки и не зависят от них — обычно ошибка ввода |
| `OPEN_END` | Работы без последователей, не ведущие к вехе | Задержка такой работы не видна ни одной вехе |
| `NO_RESOURCES` | Работы без ресурсов | Не участвуют в расчёте загрузки |
| `LONG_TASK` | Работы длиннее 66 рабочих дней (~3 месяца) | Плохо управляются и скрывают риск; стоит разбить |
| `NEGATIVE_LAG` | Связи с опережением | Допустимы, но часто маскируют ошибку логики |
| `HIGH_LAG` | Задержка связи больше стартового порога (20 рабочих дней) | Большая пауза между работами часто скрывает пропущенную работу |
| `HARD_CONSTRAINTS` | Жёсткие даты больше чем у 5% работ | План становится заданным вручную; оптимизации не остаётся места |
| `STALE_PLANNED` | Работы должны были начаться до даты статуса, но не начаты | Исходный план устарел |
| `NONWORKING_DATE` | Дата на нерабочем дне (информационно) | Расхождение календарей источников |

Проверки построены по мотивам DCMA 14-Point Assessment и обзора GAO-16-89G и подстроены под ОКР. Это стартовые пороги пилота, а не норматив: длинная работа — больше 66 рабочих дней (в DCMA для детального планирования часто 44), жёсткие даты — больше 5 % работ и не меньше 6 штук, большая задержка связи — больше 20 рабочих дней. Пороги меняются переменными `SYNAPS_PROGRAMPLAN_LONG_TASK_WD`, `SYNAPS_PROGRAMPLAN_HARD_SHARE`, `SYNAPS_PROGRAMPLAN_HARD_MIN_COUNT` и `SYNAPS_PROGRAMPLAN_HIGH_LAG_WD`. «Не раньше» считается жёстким ограничением и учитывается в `HARD_CONSTRAINTS`. Отрицательный резерв — это `DEADLINE_IMPOSSIBLE` в конфликтах исходного плана. Из четырнадцати проверок DCMA сделаны те, что перечислены в таблице выше. Пороги согласуются с заказчиком на пилоте.

## Причины переносов (`explanations[].cause_code`)

| Код | Что держит начало работы |
|---|---|
| `DEPENDENCY` | Связь с предшественником в той же ОКР |
| `CROSS_PROJECT_DEPENDENCY` | Связь с работой другой ОКР |
| `DEPENDENCY_DONE` | Связь с уже выполненной или выполняемой работой |
| `RESOURCE_CONTENTION` | Ресурс занят работами других ОКР (названы работы и ОКР) |
| `RESOURCE_BUSY` | Ресурс занят работами той же ОКР |
| `CALENDAR_CLOSURE` | Ресурс недоступен: отпуск, ремонт, внешняя бронь |
| `CAPACITY_RESERVE` | Ресурс свободен, но вариант держит запас ёмкости (вариант «Ресурсы»), и остатка не хватает работе |
| `WINDOW_STATUS_DATE` | Нельзя начать раньше даты статуса |
| `WINDOW_EARLIEST_START` | Ограничение «не раньше» |
| `WINDOW_SHIFT_LIMIT` | Достигнут лимит сдвига |
| `WINDOW_PINNED` | Работа закреплена |
| `WINDOW_FROZEN` | Работа в зоне заморозки |
| `WINDOW_IN_PROGRESS` | Работа уже выполняется |
| `WINDOW_SCENARIO` | Ограничение варианта: стабильность (не раньше утверждённого), ручная правка (работа закреплена планировщиком) или пересчёт с минимумом перестановок (не раньше, чем в исходном варианте) |
| `OPTIMIZER_CHOICE` | Ни одно ограничение не активно; дата выбрана ради общей цели |

`chain` — цепочка связей от работы до первопричины. `counterfactual` — результат пересчёта «оставить работу на утверждённых датах»: изменение окончания программы, либо доказательство, что так нельзя. В `counterfactual.fact_kind` стоит `COUNTERFACTUAL`. У свидетеля невыполнимости на верхнем уровне `fact_kind` = `INFEASIBILITY_CONFLICT`.

`fact` — те же сведения полями, по которым строится фраза: тип, ресурс, ОКР, работа-блокер, даты, хеш плана и хеш входа. Дата в факте, которой нет у работы или у блокера, проверка отвергает. Файл, записанный до появления `fact`, по-прежнему читается: поле можно не передавать.

| `fact.kind` | Когда ставится |
|---|---|
| `PRECEDENCE` | Связь с предшественником, в том числе уже выполненным |
| `MAX_LAG` | Начало стоит ровно на максимальном лаге |
| `RESOURCE_CAPACITY` | Не хватает поимённого ресурса или остатка после запаса варианта |
| `SKILL_CAPACITY` | Не хватает компетенции |
| `CALENDAR` | Ресурс закрыт календарём, отпуском или внешней бронью |
| `MAINTENANCE` | Ресурс закрыт обслуживанием |
| `FREEZE_WINDOW` | Зона заморозки |
| `BASELINE` | Закрепление, лимит сдвига или удержание варианта на прежних датах |
| `TEST_ARTICLE` | Ресурс — опытный экземпляр |
| `STATUS_DATE`, `EARLIEST_START`, `IN_PROGRESS` | Дата статуса, «не раньше» или уже начатая работа |
| `OPTIMIZER_CHOICE` | Ни одно ограничение не активно |
| `SETUP_TRANSITION`, `MODE_SELECTION` | Зарезервированы для переналадки и режимов исполнения; в факте их ещё нет, и проверка такой тип отвергает |

## Требования в свидетеле невыполнимости (`witness[].kind`)

| Код | Требование | Подсказка |
|---|---|---|
| `deadline` | Директивный срок работы или вехи | `achievable_date`, `relax_by_wd`, `suggestion` |
| `project_deadline` | Директивный срок ОКР | то же |
| `pinned` | Закрепление | — |
| `shift_limit` | Лимит сдвига | — |
| `earliest_start` | «Не раньше» | — |
| `freeze` | Заморозка плана | — |
| `capacity_exception` | Недоступность ресурса | — |
| `max_lag` | Максимальный лаг | — |

`minimal = true` означает: снятие любого одного требования из набора делает программу выполнимой (в пределах бюджета проверок). `alone_sufficient = true` у срока означает: снять только его уже достаточно.

## Коды выхода команды

| Код | Значение |
|---|---|
| `0` | План принят, проверка чиста, программа выполнима, журнал цел; для `doctor` — стенд готов |
| `1` | Принятого плана нет, проверка нашла жёсткое нарушение, программа невыполнима или цепочка журнала нарушена; для `doctor` — есть блокирующий отказ |
| `2` | Неверные входные данные или аргументы (текст — в stderr); для `serve` — попытка открыть рабочее место без ролей на нелокальном адресе или отсутствие дополнения `[api]` |

## Журнал решений (`action`)

| Действие | Когда пишется |
|---|---|
| `accept` | Пользователь с правом решения принял вариант (только с `outcome.ok`) |
| `reject` | Пользователь с правом решения отклонил вариант |
| `repair` | Планировщик запустил пересчёт с правками; пишется и при успехе, и при отказе |

Результат проверки цепочки (`integrity`): `ok`, `records`, `broken_at` — номер первой испорченной записи, `reason` — `sequence number out of order` (номер не по порядку), `previous-hash link is broken` (запись удалена или переставлена), `record content does not match its hash` (запись изменена).

## HTTP-контур вычислений (`synaps_programplan.api`)

Без хранения и без ролей; только для вызова внутри закрытого контура.

| Запрос | Ответ |
|---|---|
| `GET /version` | 200: версия, коммит ядра, уровень зрелости |
| `POST /analyze` | 200: конфликты и качество; 422: неверная программа |
| `POST /solve` | 200 и `accepted: true` — только при `outcome.ok`; 409 и `accepted: false` — плана нет; 422 — неверный вход |
| `POST /check` | 200 только если план принят (`outcome.ok`, хеши программы и плана сходятся) и жёстких нарушений нет. 409 — план не принят, хеш не сходится или есть нарушения (`accepted: false` или `ok: false`). 422 — тело не читается или правка ссылается на неизвестную работу |
| `POST /risk` | 200: квантили, доли «в срок», драйверы; 409 — план не принят или не читается; 422 — неверная программа |

## Рабочее место (`serve`)

Все запросы, кроме страницы, требуют заголовок `Authorization: Bearer <токен>`, если роли заданы. Без ролей — только локальный адрес; запрос с другим заголовком `Host` получает 400.

| Запрос | Право | Ответ |
|---|---|---|
| `GET /` | — | Страница рабочего места (данные загружаются отдельным запросом) |
| `GET /api/data` | view | Программа, варианты, риск, роль пользователя и его права |
| `GET /api/whoami` | — | Пользователь и роль |
| `POST /api/check` | check | `{scenario, moves}` → `ok`, `hard`, нарушения, показатели с правками, сдвинутые работы; 404 — нет варианта; 409 — вариант не принят; 422 — неизвестная работа |
| `POST /api/repair` | repair | `{scenario, moves, mode}` → новый вариант `R<n>`; 409 с причиной — план с правками не принят; 422 — нет правок или правка начатой работы |
| `GET /api/decisions` | view | Записи журнала и проверка цепочки |
| `POST /api/decisions` | decide | `{scenario, action: accept/reject, reason}` → запись журнала; 409 — принять непринятый план; 422 — обоснование короче 3 символов |
| `GET /api/plans/{id}` | view | Принятый план JSON (файл) |
| `GET /api/plans/{id}/mspdi` | view | Принятый план MS Project XML (файл) |

Ответы: 401 — нет или неверный токен; 403 — роли не хватает права. Каждый ответ несёт заголовки `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`.
