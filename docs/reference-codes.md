# Справочник кодов

Все коды, которые SynAPS-ProgramPlan выдаёт в ответах, файлах планов и отчёте. Коды стабильны и предназначены для автоматической обработки; рядом всегда идёт текст на русском.

## Вердикт плана (`outcome.claim`)

| Вердикт | `ok` | Когда ставится | Чего не означает |
|---|---|---|---|
| `OPTIMAL` | да | CP-SAT доказал оптимум цели ядра на скомпилированной задаче; проверка ядра и доменная проверка чисты | Оптимум сразу по всем целям заказчика; оптимум после эвристической привязки людей |
| `FEASIBLE` | да | CP-SAT нашёл допустимый план в лимите времени; обе проверки чисты | Доказанный оптимум |
| `HEURISTIC_FEASIBLE` | да | Жадный диспетчер (`--solver greedy`); обе проверки чисты | Оптимум; доказательство невыполнимости при отказе |
| `INFEASIBLE` | нет | CP-SAT доказал невыполнимость исходной модели — без подъёма окон и без второй фазы привязки людей | «Не нашлось за отведённое время» |
| `REJECTED` | нет | Решатель вернул расписание, но проверка ядра или доменная проверка нашла жёсткое нарушение | — |
| `ERROR` | нет | Плана нет, невыполнимость не доказана: лимит времени, эвристика или урезанная модель | Невыполнимость |

Только планы с `ok = true` попадают в Гант, экспорт в MS Project, оценку риска и HTTP-ответ 200.

## Нарушения независимой проверки

Проверка (`checker.py`, команда `check`) читает программу и даты плана и не использует решатель. Важность: `hard` — план не принимается; `kpi` — отклонение показателя, план принимается; `warning` — к сведению.

| Код | Важность | Что нарушено |
|---|---|---|
| `UNKNOWN_TASK` | hard | В плане работа, которой нет в программе |
| `DUPLICATE_TASK` | hard | Работа в плане дважды |
| `MISSING_TASK` | hard | Работа программы отсутствует в плане |
| `DONE_MOVED` | hard | Выполненная работа сдвинута с фактических дат |
| `FROZEN_MOVED` | hard | Сдвинута работа из зоны заморозки |
| `PINNED_MOVED` | hard | Сдвинута закреплённая работа |
| `CALENDAR_BROKEN` | hard | Начало или окончание на нерабочем дне |
| `DURATION_MISMATCH` | hard | Длительность в плане не совпадает с программой (или с остатком выполняемой работы) |
| `HORIZON_BROKEN` | hard | Работа вне горизонта или раньше даты статуса |
| `WINDOW_BROKEN` | hard | Нарушено «не раньше» |
| `DEADLINE_MISSED` | hard | Нарушен директивный срок работы или ОКР |
| `DUE_MISSED` | kpi | Нарушен плановый срок (учитывается как просрочка) |
| `SHIFT_LIMIT_EXCEEDED` | hard | Сдвиг относительно утверждённых дат больше лимита |
| `PRECEDENCE_FS_BROKEN`, `PRECEDENCE_SS_BROKEN`, `PRECEDENCE_FF_BROKEN`, `PRECEDENCE_SF_BROKEN` | hard (warning для мягкой связи) | Связь нарушена: зазор меньше лага |
| `MAX_LAG_BROKEN` | hard (warning для мягкой связи) | Зазор больше максимального лага |
| `CAPACITY_EXCEEDED` | hard | Загрузка ресурса в какой-то день больше доступной (с учётом отпусков и ремонтов) |
| `SKILL_UNBOUND` | hard | Потребность в компетенции не закрыта человеком там, где пул неточен |
| `SKILL_MISMATCH` | hard | Назначен человек без нужной компетенции |
| `SKILL_POOL_EXCEEDED` | hard | Суммарная потребность в компетенции больше числа людей с ней |
| `SKILL_BINDING_ADVISORY` | warning | Пул точен, люди названы рекомендательно |
| `APPROXIMATED_RELATION` | warning | Связь в режиме `windows` учтена приближённо (выставляет планировщик) |

## Конфликты исходных планов

Команда `analyze` и раздел отчёта «Конфликты исходных планов». Считаются по датам, как они пришли из планов ОКР, до оптимизации.

| Код | Что найдено |
|---|---|
| `OVERLOAD` | Ресурс перегружен в исходных планах |
| `SHARED_CONTENTION` | Перегрузка общего ресурса работами двух и более ОКР |
| `SKILL_POOL_OVERLOAD` | Потребность в компетенции больше числа людей с ней |
| `LINK_BROKEN` | Исходные даты нарушают связь |
| `DEADLINE_IMPOSSIBLE` | Срок недостижим даже без учёта ресурсов (отрицательный резерв по методу критического пути) |
| `DEADLINE_AT_RISK` | Резерв мал, выше по цепочке есть перегрузки |
| `DEADLINE_MISSED_IN_SOURCE` | Исходный план уже нарушает срок |

## Качество данных

Поле `quality` в ответе `analyze`.

| Код | Что найдено | Почему важно |
|---|---|---|
| `DANGLING` | Работы без связей | Не влияют на сроки и не зависят от них — обычно ошибка ввода |
| `OPEN_END` | Работы без последователей, не ведущие к вехе | Задержка такой работы не видна ни одной вехе |
| `NO_RESOURCES` | Работы без ресурсов | Не участвуют в расчёте загрузки |
| `LONG_TASK` | Работы длиннее 66 рабочих дней (~3 месяца) | Плохо управляются и скрывают риск; стоит разбить |
| `NEGATIVE_LAG` | Связи с опережением | Допустимы, но часто маскируют ошибку логики |
| `HARD_CONSTRAINTS` | Жёсткие даты больше чем у 5% работ | План становится заданным вручную; оптимизации не остаётся места |
| `STALE_PLANNED` | Работы должны были начаться до даты статуса, но не начаты | Исходный план устарел |
| `NONWORKING_DATE` | Дата на нерабочем дне (информационно) | Расхождение календарей источников |

Проверки близки к DCMA 14-Point Assessment, распространённой практике оценки качества расписаний, но не повторяют её. В DCMA «длинная работа» — больше 44 рабочих дней в периоде детального планирования; здесь порог 66 дней, потому что работы ОКР обычно крупнее. DCMA не считает «не раньше» жёстким ограничением, а здесь оно учитывается в `HARD_CONSTRAINTS`. Полный набор из 14 проверок DCMA не реализован. Пороги стоит согласовать с заказчиком на пилоте.

## Причины переносов (`explanations[].cause_code`)

| Код | Что держит начало работы |
|---|---|
| `DEPENDENCY` | Связь с предшественником в той же ОКР |
| `CROSS_PROJECT_DEPENDENCY` | Связь с работой другой ОКР |
| `DEPENDENCY_DONE` | Связь с уже выполненной или выполняемой работой |
| `RESOURCE_CONTENTION` | Ресурс занят работами других ОКР (названы работы и ОКР) |
| `RESOURCE_BUSY` | Ресурс занят работами той же ОКР |
| `CALENDAR_CLOSURE` | Ресурс недоступен: отпуск, ремонт, внешняя бронь |
| `WINDOW_STATUS_DATE` | Нельзя начать раньше даты статуса |
| `WINDOW_EARLIEST_START` | Ограничение «не раньше» |
| `WINDOW_SHIFT_LIMIT` | Достигнут лимит сдвига |
| `WINDOW_PINNED` | Работа закреплена |
| `WINDOW_FROZEN` | Работа в зоне заморозки |
| `WINDOW_IN_PROGRESS` | Работа уже выполняется |
| `WINDOW_SCENARIO` | Ограничение варианта (например, стабильность: не раньше утверждённого) |
| `OPTIMIZER_CHOICE` | Ни одно ограничение не активно; дата выбрана ради общей цели |

`chain` — цепочка связей от работы до первопричины. `counterfactual` — результат пересчёта «оставить работу на утверждённых датах»: изменение окончания программы, либо доказательство, что так нельзя.

## Требования в свидетеле невыполнимости (`witness[].kind`)

| Код | Требование | Подсказка |
|---|---|---|
| `deadline` | Директивный срок работы или вехи | `achievable_date`, `relax_by_wd`, `suggestion` |
| `project_deadline` | Директивный срок ОКР | то же |
| `pinned` | Закрепление | — |
| `shift_limit` | Лимит сдвига | — |
| `earliest_start` | «Не раньше» | — |
| `freeze` | Заморозка плана | — |
| `capacity_exception` | Недоступность ресурса | — |
| `max_lag` | Максимальный лаг | — |

`minimal = true` означает: снятие любого одного требования из набора делает программу выполнимой (в пределах бюджета проверок). `alone_sufficient = true` у срока означает: снять только его уже достаточно.

## Коды выхода команды

| Код | Значение |
|---|---|
| `0` | План принят, проверка чиста, программа выполнима |
| `1` | Принятого плана нет, проверка нашла жёсткое нарушение или программа невыполнима |
| `2` | Неверные входные данные или аргументы (текст — в stderr) |

## HTTP-контур

| Запрос | Ответ |
|---|---|
| `GET /version` | 200: версия, коммит ядра, уровень зрелости |
| `POST /analyze` | 200: конфликты и качество; 422: неверная программа |
| `POST /solve` | 200 и `accepted: true` — только при `outcome.ok`; 409 и `accepted: false` — плана нет; 422 — неверный вход |
| `POST /risk` | 200: квантили; 409 — план не принят; 422 — неверный вход |
