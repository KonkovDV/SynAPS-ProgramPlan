# Очередь следующих шагов

Рабочий список: что по каждой функции уже сделано и что идёт следующим. Заказчик — Объединённая двигателестроительная корпорация, запрос №1 разобран в [пилоте](pilot-and-roadmap.md). Цифры берутся из [реестра утверждений](../CLAIMS_REGISTRY.md) и [описания качества](quality-assurance.md).

Последний замер (Windows, Python 3.12): 196 тестов за 11 с; пять задач PSPLIB j30 с лимитом 10 с — все пять приняты с доказанным оптимумом, в среднем 0,04 с на задачу.

| Функция | Сделано | Где в коде | Этап | Следующий шаг |
|---|---|---|---|---|
| F1. Сведение планов | Импорт MS Project XML, MPP и MPX, Primavera XER, Excel. Иерархия программа → ОКР → этап → работа. Справочник этапов в `okr_stages.json`. У ОКР есть предприятие-исполнитель. У работы могут быть изделие, конфигурация и опытный экземпляр; экземпляр занимает ресурс ёмкости 1 | `io/mspdi.py`, `io/xer.py`, `io/excel.py`, `stages.py`, `enterprises.py` | 2 | Перенос тех ограничений MS Project и Primavera, которые заказчик назовёт обязательными. Обмен с 1С через согласованную выгрузку |
| F1. Общие ресурсы | Объединение по имени и по таблице соответствий. Похожие имена показываются в отчёте, но не сливаются без решения человека | `merge.py` | 2.5 | Таблица соответствий имён заказчика вместе с его данными |
| F1. Выгрузка | Принятый план уходит в MS Project XML с датами, связями и задержками, ресурсами, назначениями, директивными сроками, базовым планом 0, хешем плана и объяснением. Обратное чтение сверяет даты, тип связи и задержку | `io/mspdi.py` | 2.6 | Выгрузка в XER и Excel |
| F2. Связи, вехи, сроки | Связи всех четырёх типов, задержки, вехи, директивные сроки, закрепление, отпуска. Несколько режимов одной работы. Состояния стенда и интервал переналадки между ними, виден на диаграмме и в причине | `compiler.py`, `checker.py`, `model.py` | 3.4 | Прерывание работы. Калибровка остаётся окном обслуживания, допуск оператора — компетенцией |
| F2. Невыполнимый срок | Свидетель находит набор требований, которые вместе не сходятся, и говорит, достаточно ли ослабить одно из них или нужен весь набор | `explanations.py` | 5.1 | Сравнение послаблений по цене для программы |
| F3. Конфликты до расчёта | Перегрузки, общий стенд, нарушенные связи, качество данных по мотивам DCMA с кодами и порогами в справочнике | `conflicts.py`, `quality.py` | 4.9 | Пороги, согласованные с заказчиком |
| F3. Риск | Треугольное распределение длительностей, реестр рисков, связанные риски, учёт максимальных задержек, в том числе от выполненных работ | `montecarlo.py` | 4 | Другие распределения, ветвления логики, автоматический выбор числа выборок |
| F4. Варианты | «Сроки», «Резерв ресурсов», «Стабильность», «Баланс», «Приоритет», «Что если», вариант с правками | `scenarios.py` | 3.3 | Параллельный расчёт вариантов |
| F4. Масштаб | Точный и жадный решатели. Учебные программы до 2 688 работ, PSPLIB j30, j60 и j120, RCPSP/max j10–j30. Первый допустимый план: 5 010 работ за 117,8 с; дальше предел жадного поиска 120 с и предел ядра в 10 000 рабочих центров | `planner.py`, `benchmarks/scale_boundary.json` | 3 | Таблица «размер — время — память» на программе заказчика |
| F5. Объяснение переноса | Причина и цепочка до первопричины. `explanation_gaps` сверяет сохранённый текст с повторным чтением плана, с хешем программы и с запасом ёмкости, записанным в плане. Вариант «что если» читается по изменённой программе. Нехватка из‑за запаса не называется отпуском | `explanations.py` | 5.2 | Сделано, тесты `test_stored_explanation_matches_a_fresh_reading_of_the_plan`, `test_what_if_reasons_are_read_from_the_changed_program`, `test_a_capacity_reserve_is_not_called_a_vacation` |
| F5. Стабильный пересчёт | Режим «минимум перестановок», разложение сдвигов, взвешенный сдвиг, порядок на стенде, сдвиги внутри окна заморозки | `edits.py` | 5.3 | Сделано, тест `test_churn_weights_early_moves_and_counts_stand_order_and_freeze` |
| F5. Рабочее место | Правка мышью, мгновенная проверка, роли, журнал решений с печатью. На диаграмме сворачиваются ОКР и этапы, есть отбор по предприятию и ресурсу, у вехи с оценкой P80 — зелёная или красная точка | `workbench.py`, `auth.py`, `report_template.html` | 6 | База данных, права по ОКР, вход через LDAP или OIDC, ответ 409 на одновременную правку |
| Только принятые планы | Расчёт, выгрузка, риск, отчёт и рабочее место отдают даты только принятого плана с совпавшими хешами. `/solve` и скачивание варианта проходят ту же сверку | `api.py`, `cli.py`, `report.py`, `publish.py`, `workbench.py` | 1.1–1.2 | Закрыто, тесты `tests/test_publish_gate.py` и `tests/test_publish_exits.py` |
| Вычислительный сервис | Отдельный модуль, рабочее место его не загружает. Тело больше 32 МиБ — 413, чужой адрес без токена — 401. `SYNAPS_PROGRAMPLAN_RATE_PER_MIN` даёт 429. Потолок работ и связей, проверка распаковки Excel, решатель в отдельном процессе при `SYNAPS_PROGRAMPLAN_MEMORY_MB` | `api.py`, `model.py`, `io/excel.py`, `isolate.py`, `docs/threat-model.md` | 1.3 | Сделано. Общий лимит на несколько процессов ставит прокси контура |
| Журнал | Цепочка хешей, печать `.head`, якорь `--anchor`, подпись HMAC ключом `SYNAPS_PROGRAMPLAN_JOURNAL_KEY` | `journal.py` | 1.4 | Сделано, тест `test_a_wrong_signature_is_rejected` |
| Поставка в контур | Лицензия, перечень компонентов, закреплённые версии, руководство администратора, хеши колёс в `requirements-hashed.txt`. Actions закреплены по SHA коммита. Цифры README и сценария показа сверяет `evidence.json` | корень, `scripts/write_delivery.py`, `scripts/fetch_wheelhouse.py`, `scripts/build_evidence.py` | 7 | Прогон установки на Astra Linux и РЕД ОС на самой этой системе, Docker и systemd, Python 3.11 |
| Пакет приёмки | ТЗ, программа и методика испытаний, демонстрация на 15 минут, сборка протокола из результатов стенда | `docs/acceptance/`, `scripts/acceptance_run.py` | 8 | Подписанный протокол на площадке заказчика |
| Зрелость | Уровень 4 по ISO 16290, подтверждён стендом | `versions.py`, `CLAIMS_REGISTRY.md` | 9 | Пилот на обезличенных данных заказчика |
