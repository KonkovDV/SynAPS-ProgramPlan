# Очередь следующих шагов

Рабочий список: что по каждой функции уже сделано и что идёт следующим. Цифры для заказчика берутся из [реестра утверждений](../CLAIMS_REGISTRY.md) и [описания качества](quality-assurance.md).

Последний замер (Windows, Python 3.12): 125 тестов за 13,5 с; пять задач PSPLIB j30 с лимитом 10 с — все пять приняты с доказанным оптимумом, в среднем 0,04 с на задачу.

| Функция | Сделано | Где в коде | Этап | Следующий шаг |
|---|---|---|---|---|
| F1. Сведение планов | Импорт MS Project XML, MPP и MPX, Primavera XER, Excel. Каждое расхождение попадает в отчёт импорта с кодом, объектом и действием. Строгий режим не записывает программу, если что-то пропущено, приближено или урезано | `io/mspdi.py`, `io/xer.py`, `io/excel.py`, `io/mpp.py`, `merge.py`, `cli.py` | 2 | Перенос тех ограничений MS Project и Primavera, которые заказчик назовёт обязательными. Обмен с 1С через согласованную выгрузку |
| F1. Общие ресурсы | Объединение по имени и по таблице соответствий. Похожие имена показываются в отчёте, но не сливаются без решения человека | `merge.py` | 2.5 | Таблица соответствий имён заказчика вместе с его данными |
| F1. Выгрузка | Принятый план уходит в MS Project XML с датами, связями и задержками, ресурсами, назначениями, директивными сроками, хешем плана и объяснением. Обратное чтение сверяет даты, тип связи и задержку | `io/mspdi.py` | 2.6 | Базовый план в выгрузке, выгрузка в XER и Excel |
| F2. Связи, вехи, сроки | Связи всех четырёх типов, задержки, вехи, директивные сроки, закрепление, отпуска | `compiler.py`, `checker.py`, `model.py` | 3.4 | Прерывание работы и несколько способов выполнения, с той же независимой проверкой |
| F2. Невыполнимый срок | Свидетель находит набор требований, которые вместе не сходятся, и говорит, достаточно ли ослабить одно из них или нужен весь набор | `explanations.py` | 5.1 | Сравнение послаблений по цене для программы |
| F3. Конфликты до расчёта | Перегрузки, общий стенд, нарушенные связи, качество данных по мотивам DCMA с кодами и порогами в справочнике | `conflicts.py`, `quality.py` | 4.9 | Пороги, согласованные с заказчиком |
| F3. Риск | Треугольное распределение длительностей, реестр рисков, связанные риски, учёт максимальных задержек, в том числе от выполненных работ | `montecarlo.py` | 4 | Другие распределения, ветвления логики, автоматический выбор числа выборок |
| F4. Варианты | «Сроки», «Резерв ресурсов», «Стабильность», «Баланс», «Приоритет», «Что если», вариант с правками | `scenarios.py` | 3.3 | Параллельный расчёт вариантов |
| F4. Масштаб | Точный и жадный решатели. Учебные программы до 2 688 работ, PSPLIB j30, j60 и j120, RCPSP/max j10–j30 | `planner.py`, `benchmarks/` | 3 | Таблица «размер — время — память» на программе заказчика |
| F5. Объяснение переноса | Причина и цепочка до первопричины для каждой сдвинутой работы | `explanations.py` | 5.2 | Автоматическая сверка текста объяснения с фактами плана |
| F5. Стабильный пересчёт | Режим «минимум перестановок» и разложение сдвигов: по связям, на общих ресурсах, без связи с правкой | `edits.py` | 5.3 | Сдвиг с весами и порядок работ на ресурсе в показателях варианта |
| F5. Рабочее место | Правка мышью, мгновенная проверка, роли, журнал решений с печатью | `workbench.py`, `auth.py` | 6 | База данных, права по ОКР, вход через LDAP или OIDC, светофор по P80, ответ 409 на одновременную правку |
| Только принятые планы | Расчёт, выгрузка, риск и отчёт отдают даты только принятого плана с совпавшими хешами | `api.py`, `cli.py`, `report.py`, `publish.py` | 1.1–1.2 | Закрыто, тест `tests/test_publish_gate.py` |
| Вычислительный сервис | Запросы больше 32 МиБ отклоняются, удалённый клиент без токена получает 401, с токенами нужен `Bearer` | `api.py` | 1.3 | Отдельный процесс и ограничение частоты запросов |
| Журнал | Цепочка хешей, печать `.head`, внешний якорь `--anchor` | `journal.py` | 1.4 | Подпись записей ключом |
| Поставка в контур | Лицензия, перечень компонентов, закреплённые версии, руководство администратора | корень, `scripts/write_delivery.py` | 7 | Хеши пакетов в списке зависимостей, установка без интернета на целевой ОС, Docker и systemd, Python 3.11 |
| Пакет приёмки | ТЗ, программа и методика испытаний, демонстрация на 15 минут, сборка протокола из результатов стенда | `docs/acceptance/`, `scripts/acceptance_run.py` | 8 | Подписанный протокол на площадке заказчика |
| Зрелость | Уровень 4 по ISO 16290, подтверждён стендом | `versions.py`, `CLAIMS_REGISTRY.md` | 9 | Пилот на обезличенных данных заказчика |
