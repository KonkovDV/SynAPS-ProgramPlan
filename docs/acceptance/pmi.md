# Программа и методика испытаний

Методика подтверждает функции F1–F5 на стенде и задаёт, что измеряет человек на площадке заказчика.

## 1. Объект

Исходный код SynAPS-ProgramPlan и зафиксированный коммит ядра SynAPS из `src/synaps_programplan/versions.py`.

## 2. Автоматическая часть

```text
python -m pytest tests -q
python scripts/lint_claims.py
ruff check src tests scripts
mypy src
```

Ожидание: все тесты проходят, формулировки совпадают с реестром утверждений, проверка типов без ошибок.

Соответствие функций и тестов — в `docs/traceability-matrix.md`. Академические прогоны лежат рядом с кодом:

- PSPLIB j30 — `benchmarks/psplib_j30.json`: 480 из 480 приняты, 476 с известным оптимумом, 472 доказаны;
- PSPLIB j60 — `benchmarks/psplib_j60.json`: 480 из 480 приняты, 405 с доказанным оптимумом;
- PSPLIB j120 — `benchmarks/psplib_j120.json`: 600 из 600 приняты, 259 с доказанным оптимумом;
- RCPSP/max j10, j20, j30 — `benchmarks/rcpspmax_*.json`: все заведомо невыполнимые задачи доказаны;
- учебные программы до 2 688 работ — `benchmarks/scale.json`: жадный план и CP-SAT приняты на каждом размере.

Сводка этих файлов в протокол:

```text
python scripts/acceptance_run.py --out out/protocol.md
```

## 3. Что измеряет человек на стенде

1. Импорт обезличенного файла заказчика (MS Project или Primavera) и сверка числа работ, связей и ресурсов с источником.
2. Конфликты: эксперт отмечает, какие найденные конфликты подтверждаются.
3. Четыре варианта на этом файле: время до первого допустимого плана, до улучшенного и до набора вариантов. Цели — в `docs/pilot-and-roadmap.md`.
4. Одна локальная правка в рабочем месте: сколько работ сдвинулось по связям, сколько на общих ресурсах и сколько без связи с правкой. Порог пилота относится к последней группе.
5. Журнал: принять и отклонить вариант, проверить `journal`, сверить `--anchor` с хешем, сохранённым вне системы.
6. Сеть: процесс на локальном адресе за прокси с TLS. Запуск на внешнем адресе без сертификата завершается отказом.

Показ заказчику на учебной программе описан в `docs/acceptance/demo-script.md`. Его собирает команда из этого сценария: `out/demo/report.html` и `out/demo/report_infeasible.html`. Эти файлы знакомят с функциями. В протокол пилота вместо них входят обезличенные планы заказчика и числа из раздела 3.

## 4. Критерий

Автоматическая часть зелёная, а пункты раздела 3 записаны в протокол с числами из вывода команд. Стендовые цифры из раздела 2 к протоколу прилагаются как есть.
