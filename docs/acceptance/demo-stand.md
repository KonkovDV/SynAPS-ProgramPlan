# Запуск на стенде заказчика

Как поставить SynAPS-ProgramPlan на машину заказчика, проверить её одной командой и провести показ, если что-то пошло не так. Порядок экрана и слова — в [сценарии показа](demo-script.md). Установка без интернета подробно — в [руководстве администратора](../admin-guide.md).

## Что нужно от стенда

| Что | Требование | Как проверить |
|---|---|---|
| ОС | Windows 10/11 или Linux x86-64. Проверено на Windows и на Ubuntu в CI | `python -c "import platform; print(platform.platform())"` |
| Python | 3.12 или новее | `python --version` |
| Память и процессор | Память показа отдельно не мерили. Программа небольшая: четыре ОКР | — |
| Браузер | Любой современный: Chromium, Firefox, Edge, Яндекс Браузер. Отчёт работает без сети | Открыть `report.html` |
| Сеть | Не нужна для расчёта и отчёта. Нужна только для установки с GitHub | — |
| Права | Запись в каталог репозитория. Администратор не нужен | — |
| Java | Не нужна. Только для чтения MPP и MPX | — |

Astra Linux и РЕД ОС на показе не заявляются: установка на них проверяется на самой системе и заносится в протокол отдельно.

## Три способа поставить

**С интернетом.** Из каталога репозитория:

```text
python -m pip install -e ".[api]"
```

Ядро SynAPS скачивается с GitHub по закреплённому коммиту, поэтому нужен `git`.

**Без интернета.** На машине с сетью, той же ОС и тем же процессором:

```text
python scripts/fetch_wheelhouse.py
```

Колесо ядра попадает в набор, только если `SYNAPS_SOURCE` указывает на каталог SynAPS с тем же коммитом, что в `requirements.lock`. Иначе в хешах ядра не будет. Каталог `wheelhouse` и файл `requirements-hashed.txt` переносятся на стенд. На стенде:

```text
python -m pip install --no-index --find-links wheelhouse -r requirements-hashed.txt
python -m pip install --no-index --no-deps wheelhouse/synaps_programplan-0.1.0-py3-none-any.whl
```

Колесо продукта скрипт собирает сам. Установка из исходников без сети не получится: ей нужен `hatchling`.

Набор собирают на той же ОС и том же процессоре, что у стенда: колесо OR-Tools с Windows на Linux не ставится.

**Без установки.** Если ставить нельзя совсем, показ идёт по уже собранным файлам: `report.html` и `report_infeasible.html` открываются в браузере как файлы. Данные лежат внутри HTML, сервер и Python не нужны. Выгрузку в MS Project и рабочее место в этом случае не показывают.

## Проверка стенда

```text
SynAPS-ProgramPlan doctor --demo out/demo
```

Команда ничего не считает и в сеть не ходит. Код выхода 0 и `"ready": true` — стенд готов. Код 1 — в списке `checks` есть строка с `"ok": false` и `"blocking": true`.

| Проверка | Что значит отказ | Что сделать |
|---|---|---|
| `python` | Python ниже 3.12 | Поставить 3.12 |
| `import:synaps.precedence` | Стоит ядро SynAPS без связей общего вида | Переустановить ядро коммитом из `pyproject.toml`, не с произвольного каталога |
| `demo_program` | В каталоге нет `program.json` | Привезти собранный `out/demo` или собрать показ заново |
| `demo_plans` | В каталоге нет файлов `plan_*.json` | Собрать каталог показа заново |
| `ortools_version` | Не та версия OR-Tools | Ставить из `requirements-hashed.txt` |
| `language_model_off` | Заданы переменные Yandex Cloud | Убрать `SYNAPS_PROGRAMPLAN_YANDEX_API_KEY` и `SYNAPS_PROGRAMPLAN_YANDEX_FOLDER` из окружения |
| `plan:<вариант>` | План изменён после расчёта, посчитан для другой программы или его причины расходятся с датами | Собрать каталог показа заново |
| `file:<имя>` | Сборка показа прервана | Собрать каталог показа заново |
| `report_matches_plan_A` | Отчёт от другой сборки | Собрать каталог показа заново |
| `import:fastapi`, `uvicorn`, `httpx` | Нет дополнения `[api]`. Не блокирует: отчёт работает, рабочего места нет | `python -m pip install -e ".[api]"` |

Без `--demo` проверяется только установка.

## Каталог показа: привезти или собрать

Цифры в README и в сценарии показа получены на машине сборки. Вариант «Сроки» ограничен 8 секундами и не доказан оптимальным, поэтому на машине другой скорости повторная сборка может дать другой план и другие цифры. Порядок:

1. Привезти уже собранный `out/demo` с машины сборки. Хеши планов не зависят от ОС: `doctor --demo` на стенде подтверждает, что это те же планы.
2. Если собирать на стенде, то один раз, заранее, командой из README:

   ```text
   SynAPS-ProgramPlan demo --projects 4 --time-limit 8 --risk-runs 40 --out-dir out/demo
   ```

   На машине, где собран каталог, команда шла около полуминуты и вернула код 0. На другой машине и время, и план могут отличаться. Цифры после сборки читают из таблицы отчёта.
3. Прерванную сборку не показывают: каталог удаляют целиком и собирают заново.

## За час до показа

1. Если стенд — клон репозитория, `git log -1` совпадает с GitHub. Если поставлен колесом, `SynAPS-ProgramPlan version` показывает версию `0.1.0` и закреплённый коммит ядра.
2. `SynAPS-ProgramPlan doctor --demo out/demo` — код 0.
3. Открыть `out/demo/report.html` и `out/demo/report_infeasible.html` в браузере. В шапке: «данные: учебные» и «лабораторный прототип, подтверждённый уровень 4».
4. Проверить на проекторе: Гант читается в масштабе «вся программа», заголовок ОКР сворачивается, список «Предприятие» отбирает одну площадку.
5. Сделать копию каталога: `out/demo-backup`. Если показ пойдёт с чужого компьютера — ещё одну на съёмном носителе.
6. Если будет рабочее место: `SynAPS-ProgramPlan serve out/demo/program.json out/demo/plan_A.json out/demo/plan_D.json --journal out/demo/decisions.jsonl --risk-runs 40` и открыть `http://127.0.0.1:8765/`. Сервер слушает только этот компьютер.

## Если что-то пошло не так

| Что видно | Почему | Что делать на показе |
|---|---|---|
| `SynAPS-ProgramPlan` не найден | Каталог `Scripts` Python не в `PATH` | `python -m synaps_programplan doctor --demo out/demo` — то же самое |
| `No module named 'synaps.precedence'` | Старое ядро | Переустановить ядро, пока открыт уже собранный отчёт |
| Отчёт пустой или без диаграммы | Браузер блокирует скрипты в файлах | Открыть через локальный сервер: `python -m http.server 8766 --bind 127.0.0.1` в `out/demo`, адрес `http://127.0.0.1:8766/report.html` |
| Цифры не совпадают со сценарием | Каталог собран на другой машине или с другим лимитом | Читать цифры из таблицы. Объяснить, что вердикт `FEASIBLE` значит «найден за лимит, оптимум не доказан» |
| `serve` пишет про роли и TLS | Указан внешний адрес | Убрать `--host`, работать на `127.0.0.1` |
| Порт 8765 занят | Предыдущий `serve` не закрыт | Закрыть процесс или `--port 8767` |
| Всё сломалось | — | Скриншоты `docs/img/*.png` и копия `out/demo-backup` |

## После показа

Каталог `out/` в git не входит. Учебные данные можно оставить. Если на стенде открывали обезличенный файл заказчика, его удаляют вместе с `out/` и журналом `decisions.jsonl`: данные заказчика не покидают его контур и в репозиторий не попадают.
