# Показ на 15 минут

Учебная программа из четырёх ОКР на четырёх площадках: конструкторское бюро, опытный завод, испытательная станция, серийный завод. Имена выдуманы, данных заказчика в показе нет. Каталог `out/` в git не входит.

В шапке отчёта написано: данные учебные, подтверждённый уровень 4. Эффект из карточки запроса измеряется на пилоте рядом с текущим процессом. Языковая модель на показе выключена и в сеть не ходит.

Файлы уже собраны командой ниже. Повторный запуск с другим лимитом времени даст другой план.

| Что сказать | Цифра этой сборки |
|---|---|
| Вариант «Сроки» принят, окончание программы | 23.08.2028, просрочка вех 139 р.д., сдвинута 71 работа |
| Второй стенд ТС-1, только таблица | Окончание 12.10.2028, просрочка 89 р.д. |
| Без ОКР-4, только таблица | Окончание 05.07.2028, просрочки нет, вердикт OPTIMAL |
| P80 окончания программы по принятому плану | 09.03.2029. Сильнее всего сдвигает повторные испытания: 40 р.д. |
| Невыполнимый срок | Одна директивная дата: веха испытаний ОКР-4, 14.12.2027 |

## Перед входом

Открыть `out/demo/report.html` и `out/demo/report_infeasible.html` заранее, чтобы не ждать расчёт при заказчике. Если этих файлов нет, из каталога репозитория один раз:

```text
SynAPS-ProgramPlan demo --projects 4 --time-limit 8 --risk-runs 40 --out-dir out/demo
```

Код выхода 0. Пока файлы уже лежат в `out/demo`, команду не повторяют: другой лимит времени или другая машина могут сменить цифры в таблице выше.

Последняя проверка перед входом:

```text
SynAPS-ProgramPlan doctor --demo out/demo
```

Код 0 и `"ready": true` — установка в порядке, каждый план сверен с программой по хешам, отчёт собран из этих планов. Установка на чужую машину и запасные пути — в [инструкции для стенда](demo-stand.md).

Пять требований карточки, по порядку экрана: сводный план из четырёх ОКР — таблица и диаграмма; связи, вехи и обязательные сроки — диаграмма и страница невыполнимого срока; конфликты — раздел до выравнивания; несколько вариантов и их влияние — таблица сравнения; Гант, загрузка, критические работы и причины — диаграмма, тепловая карта, флажок «только критические» и таблица переносов. Эффект из карточки на этом экране не называют: его измеряют на пилоте.

## 0–2 минуты. О чём система

Одна программа из нескольких ОКР. Общие люди и испытательные стенды. План попадает на экран после трёх условий: решатель нашёл расписание, проверка ядра чиста, независимая проверка тоже чиста. Сдвиг работы объясняется ресурсом, связью или календарём. Просрочка 139 рабочих дней — расхождение с исходными плановыми сроками, когда стенд и человек больше не заняты двумя ОКР в один день.

## 2–8 минут. Отчёт сверху вниз

1. **Сравнение вариантов.** «Сроки», запас по ресурсам, устойчивость, баланс и приоритет переключаются на диаграмме. «Второй стенд ТС-1» и «без ОКР-4» меняют саму программу, поэтому их полосы на эту диаграмму не наносятся: в списке у них пометка «только в таблице», а цифры влияния — в строке таблицы. На этой сборке просрочка вех у «Сроков» 139 рабочих дней, у второго стенда 89, без ОКР-4 просрочки нет. Окончание программы при этом своё у каждой строки, его читают из таблицы, не из памяти. Пик загрузки 100 % значит, что самый занятый ресурс в какой-то день выбран целиком. Принятый план с перегрузкой сверх ёмкости на экран не попадает. Вердикт `OPTIMAL` у «Приоритета» и у «без ОКР-4» — оптимум по цели этого варианта. У «Сроков» вердикт `FEASIBLE`: план принят, за 8 секунд доказательство, что короче нельзя, не завершилось. Вариант «Ресурсы» держит 20 % запаса на общих ресурсах. На этой сборке его цена — окончание 25.01.2029 и просрочка 295 рабочих дней вместо 139. Это плата за запас, не сбой расчёта.
2. **Диаграмма.** Заголовок ОКР сворачивает ветку. Список «Предприятие» оставляет одну площадку. «Только критические» и «исходный план» показывают, что сдвинулось относительно исходных дат. У вехи с оценкой P80 зелёная точка — P80 не позже срока, красная — позже.
3. **Почему работы перенесены.** Самый большой сдвиг на этой сборке: «Государственные и сертификационные испытания: работа 3» на 186 рабочих дней, потому что испытатель TESTER-2 16.05.2028 занят предварительными испытаниями ОКР-2. Веха тех же испытаний ОКР-3 сдвинута на 178 рабочих дней: она ждёт работу, которую держит стенд ТС-1.
4. **Конфликты исходных планов.** Это снимок до выравнивания. На этой сборке: 5 споров за общий ресурс, 13 перегрузок пулов специалистов, 2 разорванные связи, 2 срока под угрозой.
5. **Риск.** P80 окончания программы по принятому плану — 09.03.2029. Карточка «все директивные сроки соблюдены, 100 % выборок» говорит о жёстких сроках. Просрочка 139 рабочих дней в таблице сверху — это плановые сроки. Сильнее всего P80 сдвигают повторные испытания после отказа на стенде: 40 рабочих дней. Это разброс уже построенного плана, не отдельный робастный расчёт.

## 8–11 минут. Невыполнимый срок

Открыть `out/demo/report_infeasible.html`. Дат сводного плана там нет. В `out/demo/witness_infeasible.json` на этой учебной программе одно требование: директивный срок вехи государственных и сертификационных испытаний ОКР-4, 14.12.2027. Фраза «Достаточно ослабить любое из них» появляется, только когда таких требований несколько и снятия любого одного уже хватает. Здесь её нет, и говорить её не нужно.

## 11–15 минут. Туда и обратно в MS Project

Команда `demo` уже пишет `out/demo/plan.xml` рядом с принятым планом. Команды ниже перезаписывают этот файл и читают его обратно.

Принятый план:

```text
SynAPS-ProgramPlan export out/demo/program.json out/demo/plan_A.json --out out/demo/plan.xml
SynAPS-ProgramPlan import out/demo/plan.xml --codes demo --strict --out out/demo/imported.json
```

Первая команда пишет только принятый план: даты, связи, ресурсы, директивный срок, базовый план 0 и хеш в примечании. Вторая с `--strict` завершается кодом 0. Файл MS Project — один проект: четыре ОКР в нём суммарные задачи, предприятия в этот формат не пишутся и при обратном чтении не восстанавливаются. В примечаниях будет, что «Инженер-конструктор 1» и «Инженер-конструктор 2» похожи и не слиты: без строки в таблице соответствий одноимённые люди остаются разными. Это действие `info`, импорт оно не останавливает.

Файл с ограничением «как можно позже», которое контур не переносит:

```text
SynAPS-ProgramPlan import docs/acceptance/lossy.xml --codes demo --strict --losses out/demo/losses.json --out out/demo/not-written.json
```

Код выхода 2, файл программы не создаётся. В `out/demo/losses.json` у записи код `CONSTRAINT_UNSUPPORTED`, объект и действие `skipped`.

Если останется минута: `SynAPS-ProgramPlan serve out/demo/program.json out/demo/plan_A.json --journal out/demo/decisions.jsonl --risk-runs 40` и перетащить работу раньше предшественника. Проверка сразу покажет нарушение, в отчёт такая дата не попадёт. На этом экране в таблице один вариант — тот, который передали в команду. Сравнение всех вариантов смотрят в `report.html`.
