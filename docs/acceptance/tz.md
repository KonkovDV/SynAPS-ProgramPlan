# Техническое задание на лабораторный прототип SynAPS-ProgramPlan

Статус: внутренний документ прототипа, не подписанный заказчиком. Исходный внешний документ требований в репозитории отсутствует; пункты F1–F5 ниже — формулировка, по которой собран прототип. Перед опытной эксплуатацией этот текст сверяют с документом заказчика и при расхождении правят требования, а не отчёт.

## 1. Назначение

Свести несколько планов опытно-конструкторских работ в одну программу, найти конфликты за людей и стенды, построить допустимый сводный план и несколько альтернатив, оценить разброс сроков и оставить прослеживаемое решение человека.

Расчёт выполняется в закрытом контуре. Прототип не обращается к внешней сети.

## 2. Функции

| Код | Функция | Как проверяется |
|---|---|---|
| F1 | Загрузка и объединение планов ОКР из MS Project XML, MPP/MPX, Primavera P6 XER и Excel | Автоматические тесты импорта и объединения, см. программу и методику |
| F2 | Связи четырёх типов с лагами, вехи, директивные и плановые сроки, закрепление, заморозка, отпуска и ремонты | Тесты планировщика и календаря |
| F3 | Конфликты исходных планов и оценка разброса сроков по принятому плану | Тесты конфликтов и риска |
| F4 | Несколько вариантов плана и их показатели | Тесты сценариев, включая приоритет ОКР |
| F5 | Диаграмма, загрузка, причины переносов, ручная правка, журнал решений | Тесты рабочего места и журнал |

План попадает в отчёт, экспорт и ответ HTTP 200 только после двойной проверки. Независимая проверка не использует код решателя.

## 3. Что в прототип не входит

Чтение 1С. Прерывание работы на время отпуска ресурса. Встроенный клиент корпоративного каталога. База данных. Одновременная правка несколькими пользователями. Подписанный протокол испытаний на данных заказчика. Оценка зрелости по государственному стандарту.

## 4. Ограничения, которые нельзя скрывать

Они перечислены в `LIMITS.md` и в реестре утверждений `CLAIMS_REGISTRY.md`. Число, которого нет в реестре, в документах для заказчика не используется.
