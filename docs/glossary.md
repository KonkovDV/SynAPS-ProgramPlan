# Глоссарий

| Термин | Значение |
|---|---|
| **ОКР** | Опытно-конструкторская работа. В системе — один проект программы |
| **Программа ОКР** | Совокупность ОКР, которые выполняются одновременно и делят ресурсы |
| **Сводный план** | Единый план всех работ программы с согласованными датами |
| **Структура работ (WBS)** | Иерархия этапов, фаз и пакетов работ внутри ОКР |
| **Работа** | Элемент плана с длительностью и потребностью в ресурсах |
| **Веха** | Мгновенное событие (длительность 0), обычно завершение этапа или контрольная точка |
| **Связь FS / SS / FF / SF** | Окончание→начало, начало→начало, окончание→окончание, начало→окончание |
| **Лаг** | Задержка в связи, в рабочих днях; отрицательный лаг — опережение |
| **Максимальный лаг** | Наибольший допустимый зазор: последователь должен начаться (закончиться) не позже |
| **Директивный срок** | Жёсткий срок (`deadline`, `latest_finish`): план с нарушением не принимается |
| **Плановый срок** | Мягкий срок (`due_date`): нарушение допускается и минимизируется как просрочка |
| **Просрочка** | Сумма опозданий относительно плановых сроков, в рабочих днях |
| **Дата статуса** | «Сегодня» плана: ничего нового не начинается раньше неё |
| **Утверждённый план (база)** | Даты, от которых считаются сдвиги: база программы, базовый план MS Project или исходные плановые даты |
| **Сдвиг** | Разница между новым и утверждённым началом работы, в рабочих днях |
| **Лимит сдвига** | Допустимый сдвиг работы относительно утверждённого плана |
| **Закрепление (pinned)** | Работа должна остаться на утверждённых датах |
| **Заморозка** | Работы ближайшего горизонта, которые не двигаются при перепланировании |
| **Ресурс** | Человек, группа, стенд, лаборатория, оборудование или ПО с ёмкостью |
| **Общий ресурс** | Ресурс, нужный двум и более ОКР — источник конкуренции |
| **Компетенция (пул)** | Группа людей с одним навыком; потребность может быть закрыта любым из них |
| **Привязка** | Назначение конкретного человека на потребность в компетенции |
| **Ёмкость** | Сколько ресурса доступно в день: людей — в десятых долях ставки, стендов — в штуках |
| **Перегрузка** | Потребность в ресурсе в какой-то день больше его доступности |
| **Критический путь** | Цепочка работ без резерва: задержка любой из них сдвигает окончание |
| **Резерв (float)** | На сколько работу можно задержать, не сдвигая окончание (без учёта ресурсов) |
| **Вариант (сценарий)** | Один из планов A–E, построенный по своей цели, или вариант R — с ручными правками |
| **Правка** | Перенос работы планировщиком на новую дату в режиме правки диаграммы Ганта |
| **Пересчёт с правками** | Новый вариант, в котором правки закреплены, а остальное перестроено: с минимумом перестановок или с переоптимизацией сроков |
| **Минимум перестановок** | Режим пересчёта: ни одна другая работа не раньше, чем в исправляемом варианте, суммарное запаздывание относительно него минимально |
| **Рабочее место** | Сервер `serve`: отчёт с правкой, проверкой, пересчётом, решениями и журналом |
| **Роль** | Планировщик (всё), руководитель (смотреть, проверять, принимать решения), наблюдатель (смотреть и проверять) |
| **Журнал решений** | Файл записей «кто, когда, какой вариант принял или отклонил и почему», связанных хеш-цепочкой |
| **Хеш-цепочка** | Каждая запись содержит хеш предыдущей, поэтому изменение, удаление или перестановка записи внутри журнала обнаруживаются |
| **Что если** | Вариант на изменённой программе: ёмкость, сроки, состав, длительности |
| **Вердикт** | Итог расчёта: `OPTIMAL`, `FEASIBLE`, `HEURISTIC_FEASIBLE`, `INFEASIBLE`, `REJECTED`, `ERROR` |
| **Принятый план (`outcome.ok`)** | План, прошедший решатель, проверку ядра и независимую доменную проверку |
| **Независимая проверка** | Повторная проверка всех правил по исходной программе без решателя |
| **Объяснение (причина)** | Ограничение, которое держит начало работы в итоговом плане |
| **Первопричина** | Ограничение в конце цепочки связей: ресурс, окно или календарь |
| **Контрфакт** | Пересчёт «что, если оставить работу на утверждённых датах» |
| **Свидетель невыполнимости** | Небольшой набор требований, которые вместе несовместимы, с подсказкой, что ослабить |
| **P50 / P80 / P90** | Даты, раньше которых закончились 50%, 80%, 90% прогонов оценки риска (выборочные квантили, не доказанная вероятность) |
| **Индекс критичности** | Доля прогонов, в которых работа оказалась без резерва |
| **Доля «в срок»** | Доля прогонов оценки риска, в которых веха уложилась в свой срок |
| **Драйвер риска** | Именованный риск с вероятностью и влиянием на длительность группы работ, например «повторные испытания после отказа на стенде» |
| **Выигрыш P80** | На сколько рабочих дней раньше стал бы P80 окончания программы, если бы риска не было; по нему драйверы ранжируются |
| **Общие случайные числа** | Приём сравнения: прогоны с риском и без него используют одни и те же случайные величины, поэтому разница — эффект именно этого риска |
| **Происхождение (provenance)** | Откуда данные: синтетика, открытые данные, обезличенные данные заказчика, эксперимент |
| **Доказательная база (evidence)** | Версии, коммит ядра, хеши входа, настроек и плана — всё, чтобы повторить расчёт |
| **CP-SAT** | Решатель ограничений Google OR-Tools, используемый ядром SynAPS |
| **SynAPS** | Ядро планирования, на котором построена система |
| **MSPDI** | Формат MS Project XML |
| **XER** | Текстовый формат выгрузки Primavera P6 |
| **PSPLIB** | Открытая библиотека эталонных задач календарного планирования с ограниченными ресурсами; j30 — 480 задач по 30 работ с известными оптимумами |
| **RCPSP / RCMPSP** | Задача календарного планирования с ограниченными ресурсами (одно- и многопроектная) |
| **TRL / УГТ** | Уровень готовности технологии по ISO 16290 / ГОСТ Р 58048 |
