# SynAPS-ProgramPlan

Сводный план программы ОКР. Несколько проектов, общие специалисты и стенды, связи и сроки собираются в один план, который проверен дважды. Для каждого переноса работы видно, почему он случился, а для каждого срока — насколько он под угрозой.

## Зачем это нужно

Когда программу ведут из нескольких планов ОКР, сводный план собирают вручную. На это уходят дни, а конфликт за общий стенд обычно всплывает уже после того, как планы сведены. Доказать, что директивный срок невыполним, и показать, какое требование достаточно ослабить, в таком процессе почти невозможно. После любой правки непонятно, почему сдвинулось всё остальное.

SynAPS-ProgramPlan закрывает эти места:

- читает планы из MS Project, Primavera P6 и Excel и сводит их в одну программу;
- находит конкуренцию за людей и стенды ещё до расчёта;
- строит согласованный план и несколько вариантов, чтобы руководитель выбирал между ними, а не между догадками;
- если срок невыполним, доказывает это и называет требования, из-за которых он не сходится;
- объясняет каждый перенос: какая связь, какой ресурс или какое окно держит работу;
- оценивает риск срыва вех и показывает, какой риск сильнее всего сдвигает срок программы;
- даёт планировщику править план мышью и сразу проверяет правку;
- записывает каждое решение в журнал, который нельзя незаметно исправить задним числом.

Расчёт выполняет ядро [SynAPS](https://github.com/KonkovDV/SynAPS) на решателе Google OR-Tools CP-SAT. Любой план, и рассчитанный, и исправленный вручную, затем проходит вторую проверку, которая написана отдельно от решателя и не использует его код.

## Что получает руководитель программы

| Требование | Как оно выполнено |
|---|---|
| **F1. Сводный план** из планов отдельных ОКР | Читаются файлы MS Project (XML, а через библиотеку MPXJ и MPP с MPX), выгрузки Primavera P6 XER с несколькими проектами в одном файле и книга Excel. Одинаковые ресурсы из разных файлов становятся общими. Если один стенд в файлах назван по-разному, их сводит таблица соответствий. Межпроектные связи для MS Project задаются таблицей CSV. Всё, что импорт перенёс не один в один, попадает в отчёт с кодом. В строгом режиме программа без полного переноса не записывается |
| **F2. Связи, вехи, сроки и ограничения** | Четыре типа связей с задержкой и максимальной задержкой. Вехи. Директивные и плановые сроки. Лимит сдвига, закрепление, заморозка ближних недель. Отпуска людей и ремонты стендов. Российский производственный календарь по постановлениям Правительства на 2025–2027 годы |
| **F3. Конфликты и риск срыва** | До расчёта: перегрузки, борьба ОКР за один ресурс, нарушенные связи, невозможные и рискованные сроки, ошибки в исходных данных. После расчёта: даты P50, P80 и P90 для программы и каждой вехи, доля случаев, когда веха укладывается в срок, критичность работ и реестр рисков с оценкой, на сколько каждый риск сдвигает P80 |
| **F4. Варианты плана** | «Сроки», «Резерв ресурсов», «Стабильность», «Баланс», «Приоритет ОКР», «Что если» (добавить стенд, перенести веху, исключить ОКР, удлинить работу) и вариант с правками планировщика. Все варианты сведены в одну таблицу сравнения, совпадающие объединены |
| **F5. Гант, загрузка, критические работы, причины изменений** | Отчёт открывается в браузере без сети. Рабочее место планировщика: диаграмма Ганта, перенос работ мышью и с клавиатуры, мгновенная проверка, пересчёт с минимумом перестановок, тепловая карта загрузки, причина каждого переноса, решения с обоснованием в журнале, роли пользователей, выгрузка принятого плана обратно в MS Project |

Какой код и какой тест закрывает каждое требование, показано в [`docs/traceability-matrix.md`](docs/traceability-matrix.md).

## Почему плану можно доверять

План попадает в отчёт, на диаграмму, в рабочее место и в ответ сервиса только при трёх условиях сразу:

1. решатель нашёл допустимое расписание;
2. проверка ядра SynAPS не нашла нарушений;
3. независимая проверка заново прошла по срокам, связям, загрузке, календарю и закреплениям и тоже ничего не нашла.

Правка, сделанная мышью, проходит ту же независимую проверку, что и рассчитанный план. Каждый план несёт хеш входных данных и хеш результата. Если даты в файле плана изменили, а хеш остался прежним, или план считали для другой программы, его не покажут и не выгрузят.

У каждого расчёта один итог:

| Итог | Что он означает |
|---|---|
| `OPTIMAL` | План принят, и доказано, что по заданной цели лучше нельзя |
| `FEASIBLE` | План принят и проверен. Решатель нашёл хорошее решение, но за отведённое время не успел доказать, что лучшего нет |
| `HEURISTIC_FEASIBLE` | План принят и проверен. Построен быстрым жадным методом |
| `INFEASIBLE` | Доказано, что при этих сроках, связях и ресурсах программа невыполнима. Система называет несовместимые требования и подсказывает, насколько их сдвинуть |
| `REJECTED` | Решатель что-то вернул, но проверка нашла нарушение. Такой план не показывается |
| `ERROR` | Плана нет, а невыполнимость не доказана: например, закончилось время расчёта |

Все итоги и коды нарушений описаны в [`docs/reference-codes.md`](docs/reference-codes.md).

## Как попробовать

Нужен Python 3.12 или новее.

```text
pip install "SynAPS-ProgramPlan[api] @ git+https://github.com/KonkovDV/SynAPS-ProgramPlan.git"
SynAPS-ProgramPlan demo --out-dir out/demo
SynAPS-ProgramPlan serve out/demo/program.json out/demo/plan_A.json out/demo/plan_D.json --journal out/demo/decisions.jsonl --risk-runs 200
```

Команда `demo` за одну–три минуты создаёт учебную программу из четырёх ОКР с общими стендами, специалистами и реестром рисков, строит варианты и складывает в `out/demo`:

- `report.html` — отчёт по вариантам с разделом о риске;
- `report_infeasible.html` — пример программы с невыполнимым сроком и разбором, что именно не сходится;
- `program.json`, `plan_*.json`, `risk_A.json` — исходные данные, планы с хешами и оценка риска.

Команда `serve` открывает рабочее место по адресу `http://127.0.0.1:8765/`. Это тот же отчёт, в котором можно править план, пересчитывать его, принимать решения и вести журнал.

## Рабочий цикл

| Шаг | Команда | Что получается |
|---|---|---|
| 1. Шаблон | `SynAPS-ProgramPlan template --out program.xlsx` | Книга Excel со всеми листами, включая реестр рисков |
| 2. Сводная программа | `SynAPS-ProgramPlan import okr1.xml okr2.xml --codes okr1 okr2 --links links.csv --aliases names.csv --strict --losses losses.json --out program.json` | Одна программа с общими ресурсами и отчёт импорта. В строгом режиме неполный перенос возвращает код 2 и программа не записывается |
| 3. Конфликты | `SynAPS-ProgramPlan analyze program.json` | Перегрузки, конкуренция за ресурсы, нарушенные связи, рискованные сроки, ошибки в данных |
| 4. Варианты | `SynAPS-ProgramPlan scenarios program.json --out-dir out --explain` | Планы и таблица сравнения |
| 5. Невыполнимый срок | `SynAPS-ProgramPlan witness program.json` | Несовместимые требования и то, насколько их нужно ослабить |
| 6. Риск | `SynAPS-ProgramPlan risk program.json out/plan_A.json --out risk.json` | P50, P80, P90, вероятность уложиться по каждой вехе, вклад каждого риска |
| 7. Отчёт | `SynAPS-ProgramPlan report program.json out/plan_A.json out/plan_D.json --risk-runs 200 --out report.html` | Сравнение, Гант, загрузка, риск, причины переносов |
| 8. Рабочее место | `SynAPS-ProgramPlan serve program.json out/plan_A.json out/plan_D.json --journal decisions.jsonl` | Правка, проверка, пересчёт, решения, журнал |
| 9. Проверка правок без сервера | `SynAPS-ProgramPlan check program.json out/plan_A.json --moves edits_A.json`, затем `replan … --moves edits_A.json --out plan_R1.json` | Нарушения, которые вносят правки, и новый вариант с закреплёнными правками |
| 10. Обратно в MS Project | `SynAPS-ProgramPlan export program.json out/plan_A.json --out plan_A.xml` | Принятый план с датами, связями, ресурсами, сроками и хешем плана |
| 11. Новая дата статуса | `SynAPS-ProgramPlan repair program.json out/plan_A.json --status-date 2027-03-01 --freeze-wd 10 --out plan2.json --out-program program2.json` | План от новой даты, ближайшие 10 рабочих дней не трогаются |
| 12. Журнал | `SynAPS-ProgramPlan journal decisions.jsonl --tail 5` | Последние решения и проверка, что журнал не изменён |

Каждый шаг с примерами разобран в [`docs/user-guide.md`](docs/user-guide.md).

## Какой эффект ожидается и как его измерить

| Эффект | За счёт чего | Чем измеряется на пилоте |
|---|---|---|
| Меньше труда на сводный план | Импорт и слияние планов, автоматический поиск конфликтов, пересчёт одной командой | Человеко-дни на один цикл актуализации до и после |
| Реалистичные планы | Принимается только план без перегрузок и нарушенных связей, правка проверяется по тем же правилам | Доля работ, начатых в плановое окно |
| Меньше сорванных сроков | P80 и вероятность уложиться по каждой вехе, вклад каждого риска, варианты «что если», доказательство невыполнимости | Просрочка вех, P80 до и после мер |
| Обоснованное распределение специалистов и стендов | Конкуренция за ресурс видна до расчёта, варианты с резервом и балансом, загрузка по дням | Перегрузки и пиковая загрузка в каждом варианте |
| Прозрачные решения | Причина каждого переноса, журнал «кто, что и почему решил» с привязкой к версии плана | Оценка понятности экспертами, полнота журнала |

Порядок пилота и критерии приёмки — в [`docs/pilot-and-roadmap.md`](docs/pilot-and-roadmap.md).

## Данные заказчика

Данные заказчика не хранятся в репозитории и не покидают закрытый контур. В работу берутся только обезличенные планы. У каждой программы записано происхождение: учебные данные, открытый набор, обезличенные данные заказчика или эксперимент. Отчёт показывает его на первом экране. Рабочее место без настроенных ролей отвечает только на этом же компьютере. Языковые модели в расчёте не участвуют: они не создают ограничений и не меняют план, а объяснения строятся только из фактов проверенного плана. Подробнее — в [`docs/security-and-data.md`](docs/security-and-data.md).

## Для разработчиков

```text
git clone https://github.com/KonkovDV/SynAPS-ProgramPlan.git
cd SynAPS-ProgramPlan
pip install -e ".[dev,api]"
python -m pytest tests -q
python scripts/lint_claims.py
ruff check src tests scripts
mypy src
```

Ядро SynAPS подключается напрямую, без отдельной копии, и закреплено коммитом `786cf1b3bc915941558e7e50b2935de684a32643`. Тот же коммит указан в `src/synaps_programplan/versions.py`, `pyproject.toml` и `CLAIMS_REGISTRY.md`, а тест `tests/test_pin.py` следит, чтобы они совпадали. Связи общего вида добавлены в ядро в [KonkovDV/SynAPS#45](https://github.com/KonkovDV/SynAPS/pull/45).

Запуск из исходников: `python -m synaps_programplan`. Сервисов два. Рабочее место `SynAPS-ProgramPlan serve` хранит журнал, проверяет роли и за пределами локального адреса работает только по TLS. Вычислительный сервис `uvicorn synaps_programplan.api:app` ничего не хранит: на локальном адресе он отвечает сразу, с любого другого — только по токену. Прогон открытых наборов: `python scripts/bench_psplib.py`.

Коды выхода: `0` — план принят или проверка прошла, `1` — принятого плана нет или найдено нарушение, `2` — ошибка во входных данных.
